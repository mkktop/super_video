# 设置页重设计实施提示词

> 用途：交给另一个 AI 执行具体的界面重设计。以下内容基于对现有代码的实际分析，包含全部必要的上下文、设计规范和验收标准。

---

## 一、项目背景与技术约束

这是一个 **Electron + Vue 3 + TypeScript** 桌面应用（视频超分工具），UI 库为 **Naive UI**（v2.45），构建工具 electron-vite，包管理 pnpm。

**目标文件**：`app/src/renderer/src/pages/Settings.vue`（本次只改这一个文件；如确有必要可新增少量样式，但不要动其他页面）。

**必须遵守的硬性约束**：

1. **不要改动任何业务逻辑**：`<script setup>` 中的全部状态、composables（`useScheduleGate` / `useOutputSettings` / `useCompareCache` / `useTrtComponent` / `useAppUpdate`）、`api.saveSettings` 调用、保存成功/失败回滚逻辑、`onMounted` 初始化流程，全部原样保留。本次任务**只重构 `<template>` 结构和 `<style scoped>`**。
2. **必须使用现有设计令牌**，禁止引入新的色值。主题变量定义在 `App.vue` 中，深浅色双主题都靠它们切换：
   - 面板/卡片：`--sv-panel`、`--sv-panel-hi`、`--sv-panel-2`、`--sv-well`（内嵌深井，用于路径框/代码块）
   - 边框：`--sv-border-soft`（发丝分隔线）、`--sv-border-mid`、`--sv-border-strong`
   - 文字：`--sv-text`（主）、`--sv-text-dim`（次）、`--sv-text-faint`（弱）、`--sv-text-code`（等宽）
   - 语义色：`--sv-accent`、`--sv-success`、`--sv-warning`、`--sv-danger` 及对应 `--sv-*-bg` 浅底色
   - 填充层：`--sv-fill-1/2/3`
   - 间距：`--sv-space-1/2/3/…`（4px 基准）
3. 卡片基础样式 `.sv-card`（底色/描边/圆角/阴影）是全局类，继续使用，不要在 scoped 样式里重复造卡片壳。
4. Naive UI 组件尺寸统一 `size="small"`，与项目其他页面保持一致。
5. 页面最小宽度 560px（`min-width: 560px`，窄于此横向滚动，不挤压控件）——这条现有规则保留。
6. 深浅色主题下都必须可读，任何文字颜色都要走 token，禁止写死颜色。

## 二、现状问题诊断（为什么要重设计）

当前布局是「左右两列卡片 + 底部设备信息通栏」，共 **11 张卡片**：

| 列 | 卡片 | 保存交互 |
|---|---|---|
| 左列 | 处理引擎（后端/精度/双路并行） | 手动按「保存」按钮（有脏状态提示） |
| 左列 | TensorRT 加速组件（安装/卸载，条件渲染） | 操作型按钮 |
| 左列 | 通知与窗口（任务通知/关到托盘/队列完成后动作） | 开关和 Select 即时保存 |
| 左列 | 处理时机（立即/时段/空闲） | 手动按「保存」按钮 |
| 右列 | 外观（主题 + 快捷键对照表） | 主题即时生效（localStorage） |
| 右列 | 输出位置（目录选择/命名模板/删源文件） | 命名模板手动保存，删源文件即时保存 |
| 右列 | 对比（静帧样本数/缓存清理） | 样本数手动保存，清缓存有二次确认 |
| 右列 | 应用与更新（版本/通道/下载源/自动检查） | 单选与开关即时保存 |
| 右列 | 性能监控（后台采样/超分性能日志） | 开关即时保存 |
| 右列 | 模型下载（代理模式/自定义地址） | 手动按「保存」按钮 |
| 通栏 | 设备信息（纯展示规格表） | 无 |

用户反馈"混乱"，具体问题是：

1. **无导航**：11 个设置域堆在滚动页面里，找一个设置要靠扫读所有卡片标题。
2. **分组语义不一致**：左列叫"处理与队列"右列叫"输出与应用"，但"外观"放在右列、"性能监控"和"模型下载"也混在右列，分类边界模糊。
3. **保存心智模型不统一**：有的改动即时生效、有的要按保存、有的按了保存"下一个任务才生效"，用户无法预测行为，也没有任何视觉约定区分这三种模式。
4. **信息密度失衡**：提示文字（`.hint` / `small`）又多又长，和可操作控件混在一起；快捷键对照表和主题切换挤在同一张卡。
5. **危险操作无视觉区分**：「超分完成后删除源文件」「清理对比缓存」和普通开关长得一样。

## 三、重设计方案

### 3.1 整体布局：顶部分类导航 + 单栏内容（锚点滚动）

**背景约束（重要）**：应用外壳已经是「顶部 TitleBar + 左侧一级页面 Sidebar + 右侧 main 内容区」的结构（见 `App.vue`）。设置页内部如果再用左侧导航，会形成"双左栏"，两条竖向导航并排既挤占内容宽度又容易混淆层级。因此**分类导航必须放在页面顶部，做横向排列**。

把「两列卡片海」改为：

```
┌──────────────────────────────────────────────┐
│ 设置                                          │
│ ┌──────────────────────────────────────────┐ │
│ │ 通用  处理  输出  对比  系统  关于与设备    │ │ ← 吸顶横向导航
│ ├──────────────────────────────────────────┤ │
│ │                                          │ │
│ │      （单栏内容区，最大宽度 760px，居中）   │ │
│ │                                          │ │
│ │      各分组依次垂直排列                    │ │
│ │                                          │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **顶部导航**：一排横向分类项（六个），`position: sticky; top: 0`，z-index 高于内容卡片，底色用 `--sv-panel`（或带 `backdrop-filter` 的半透明 `--sv-panel` + 底部 1px `--sv-border-soft` 发丝线），滚动经过时内容从其下方穿过、导航保持可读。
- **导航项样式**：13px、`--sv-text-dim`，padding `6px 14px`，圆角 999px 胶囊形；激活态 = `background: var(--sv-accent-bg)` + `color: var(--sv-accent)` + 字重 600；hover 态 = `background: var(--sv-fill-2)`，过渡 150ms。不要下划线式 tab（项目里 RadioButton 已经是分段控件风格，胶囊 chips 与其区分，避免又像一级导航又像表单控件）。
- **滚动高亮（scroll-spy）**：用 `IntersectionObserver` 监听各分组 section（`rootMargin` 顶部预留导航高度，如 `-80px 0px -60% 0px`），当前可视分组对应的导航项进入激活态。
- **点击跳转**：`scrollIntoView({ behavior: 'smooth', block: 'start' })`，且每个分组 section 设 `scroll-margin-top: 72px`（导航高度 + 呼吸间距），避免标题被吸顶导航盖住。
- **右侧内容区**：`max-width: 760px; margin: 0 auto`，单栏垂直排列分组，组间距 24px。
- **响应式**：内容区宽度不足时导航项等比收窄（缩小 padding），仍放不下则导航条允许横向滚动（`overflow-x: auto`，隐藏滚动条）；页面 560px min-width 规则不变，不做导航换行（换行两排 chips 很丑）。

### 3.2 六个分组的归属（重新分类，修复语义）

| 分组 | 包含的设置域 | 说明 |
|---|---|---|
| **通用** | 外观（主题切换）；通知与窗口（任务通知 / 关到托盘 / 队列完成后动作） | 快捷键对照表从"外观"卡里拆出，移到"关于与设备"组 |
| **处理** | 处理引擎；TensorRT 加速组件；处理时机；性能监控 | 原左列核心 + 性能监控（它本质决定处理时的数据采集） |
| **输出** | 输出位置（目录 / 命名模板 / 删源文件） | 独立成组，删源文件移入危险区（见 3.4） |
| **对比** | 静帧样本数；缓存管理 | 保持现状两卡片合并为一组 |
| **系统** | 模型下载（代理）；应用与更新 | 网络与版本类 |
| **关于与设备** | 设备信息（规格表）；快捷键对照表；当前版本号 | 纯展示信息沉底 |

每个分组渲染为：
```html
<section class="settings-group" :id="group-id">
  <h2 class="group-title">分组名</h2>   <!-- 13px, --sv-text-faint, 大写间距感 -->
  <div class="group-cards">…一张或多张卡片…</div>
</section>
```

### 3.3 卡片内部规范（统一 11 张卡的骨架）

沿用现有 `.card-head`（标题 + 副题）+ `.card-body` 行式结构，但做三条统一：

1. **行布局只有一种范式**：左侧"标签 + 一行 12px 说明"，右侧控件（`justify-content: space-between`），相邻行用 `border-top: 1px solid var(--sv-border-soft)` 发丝线分隔。现有的 `.row.stack`（控件换行到标签下方）只允许在单选按钮组（推理后端、精度、领取时机）这种控件超宽的场景使用。
2. **保存行为视觉约定**（核心改进，解决心智模型混乱）：
   - **即时保存**（开关 / 主题 / 更新通道等）：控件旁不加任何按钮，说明文字里已写明"立即生效"的保持原样。
   - **手动保存**（引擎+精度、处理时机、命名模板、静帧数、代理）：卡片底部统一一个右对齐 `.save-row`（现有样式可复用），按钮文案统一为「保存」；**有未保存修改时**在按钮左侧显示橙色小圆点 + "有未保存的修改"（颜色用 `--sv-warning`）。现在只有引擎卡有脏状态（`engineDirty`），其余手动保存项也要补上等价的 dirty 判断（纯 UI 层对比"当前值 vs 从后端读到的初始值"，不改保存逻辑）。
   - **下一任务生效**类（引擎、双路并行、性能日志）：保存/切换成功后 message 已有文案，卡片副题里补充一句统一口径，不额外加 UI。
3. **提示文字降噪**：`.hint` 段落每个卡片最多一段、最多两行；超过两行的说明（如 TensorRT 安装说明、命名模板变量表）改为「说明文字 + 问号图标 ⓘ hover 弹出 NPopover」收纳。Naive UI 的 NPopover 项目里已有用法（应用与更新卡），照抄模式即可。

### 3.4 危险操作视觉区分

- 「超分完成后删除源文件」和「清理对比缓存」两项，行的左侧加一个 `--sv-danger` 色小警示图标（⚠ 或 Naive 图标），标签文字用 `--sv-danger-strong`；清理按钮维持 `type="warning" secondary` + NPopconfirm 不变。
- 「删除源文件」开关打开时，在该行下方插入一行 `--sv-danger-bg` 底色的 12px 提示条："已开启：任务成功后源文件将被永久删除，不进回收站"。

### 3.5 设备信息卡改造

从通栏规格条改为"关于"组里的紧凑卡：
- 左侧：应用名 + `v{{ appVersion }}` + 更新状态 Tag（复用现有 `updateTag`）。
- 右侧：规格表保持 `.spec-grid` 两列网格，但五项（显卡/处理器/内存/硬件编码/硬件解码）压缩为更紧凑的 `gap: 8px 24px`。
- 快捷键对照表（现有 `.sc-grid` 键帽样式原样保留）移到本组第二张卡"快捷键"。

### 3.6 细节与质感

- 分组标题 `h2.group-title`：12px、`--sv-text-faint`、`letter-spacing: 0.08em`、字重 600，下间距 8px。
- 卡片 hover 不需要动效（设置页求稳）；导航项 hover 与激活样式按 3.1 规范。
- 滚动到目标分组时，目标卡片头部短暂（1s）高亮 `--sv-accent-bg` 底色再淡出，帮助用户定位（CSS animation 实现，不用 JS 定时器之外的依赖）。
- 顶部导航项可在文字前加一个 16px 线性图标（通用=齿轮/处理=闪电/输出=文件夹/对比=分屏/系统=云下载/关于=信息圈），用 Naive UI 自带图标或内联 SVG，风格统一线性、单色 `--sv-text-dim`，激活态随文字一起变 `--sv-accent`。窄屏导航收窄时图标保留（图标+短标签比纯长文字更省横向空间）。

## 四、不要做的事

1. 不要动 `<script setup>` 里任何逻辑、变量名、API 调用、composable 用法；新增的 dirty 判断只允许是模板层 `computed` 性质的纯比较。
2. 不要引入新的依赖（不加路由、不加状态库、不加动画库）。
3. 不要改 `.sv-card`、`--sv-*` token 的定义（它们在 App.vue）。
4. 不要把设置项拆到多个路由页面——保持单页 + 锚点导航。
5. 不要改变任何设置项的后端字段名与保存时机语义（即时保存的仍是即时，手动的仍是手动）。
6. 不要删除任何现有设置项或提示信息，只能收纳（popover），不能删减。

## 五、验收标准

1. `pnpm --filter app typecheck`（或项目对应的 tsc 检查）通过，无新增 any。
2. 深浅色主题切换后，新布局所有文字、边框、导航高亮、危险区提示条均正常可读（手动目检两个主题截图）。
3. 窗口宽度从 560px 拉到全屏，布局按 3.1 的响应式规则变化，无横向挤压、无控件溢出。
4. 点击顶部导航每个分类，内容区平滑滚动到对应分组（分组标题不被吸顶导航遮住），手动滚动时导航激活态正确跟随（scroll-spy）。
5. 所有 11 个设置域的功能逐项回归：每个开关/单选/输入/按钮的保存行为与改前完全一致（含失败回滚、loading、message 文案）。
6. 手动保存类卡片在修改未保存时显示橙色脏状态点，保存成功后消失。
7. 危险两项有明显的红色视觉区分，删源文件开启后出现警示条。

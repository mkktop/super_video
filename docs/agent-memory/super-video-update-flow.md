super_video 自动更新（electron-updater 6.8.9 + electron-builder 26.0.12，仅 Windows）：交互模型为"检查→点下载（进度条）→点重启"，`autoDownload=false` 不自动下载；`disableDifferentialDownload=true`（v0.1.0→v0.1.1 差分把旧包拼成新更新两次复现，根因是资产错位+缓存复用，静默出错不报错）。发布用 `--publish never` + softprops 上传 setup.exe/latest.yml，正文源是仓库根 RELEASE_NOTES.md。**2026-08-24 起（用户要求）RELEASE_NOTES.md 只保留当前版本内容**（发版时整文件重写，历史在 git 与各版 Release 页），Release 正文自然只含本次更新；主进程 sliceNotes 对单节/无节文件都兼容（找不到 "## vX.Y.Z" 节时返回全文，恰好就是当次内容）。

**Why:** 2026-08-24 对比 D:\work\All_In_One_Video 后按 AIOV 交互模型重构（点击才下载、正文用文件、简化发布），保留禁差分；同日用户明确"更新说明只保留本次更新，不必包含历史"。2026-08-25 发 v0.1.16 犯过一次：本地打包又手动上传 exe，把 CI 已上传的配套 exe 换成了本地构建，导致 latest.yml（描述 CI 构建）与 exe 资产 sha 不配；删双资产 workflow_dispatch 重跑 release.yml 才复原（教训：发布产物一律 CI 构建，本地不上传）。

**How to apply:**
- **发版只做四件事**：升 app/package.json 版本 → 重写 RELEASE_NOTES.md 为仅本次内容（保留 `## vX.Y.Z` 节标题）→ 提交推送 → `git tag v0.1.x && git push`。**之后什么都别传**：`.github/workflows/release.yml` 会在 windows-latest 上构建（PyInstaller sidecar + 下载 BtbN ffmpeg + electron-builder `--publish never`），softprops 统一上传 dist-app/*.exe + latest.yml（正文取 RELEASE_NOTES.md），并同步 bundled 模型资产到 models-v1（幂等跳过已有）
- **发布后校验配对**（从 GitHub 下载 latest.yml，比对其中 size/sha512 与 exe 资产实际值）：CI 构建与本地构建字节不同属正常（环境差异），关键是 yml 和 exe 必须是同一次 CI 构建的配套产物；发现错配就删双资产 + `POST /actions/workflows/release.yml/dispatches {"ref":"v0.1.x"}` 重跑
- **requirements.txt 必须覆盖全部运行期 import**（v0.1.18 事故：py7zr 漏列 → CI exe 缺库，本地 venv 手工装过掩盖；PyInstaller hiddenimports 缺包只警告不报错）。release.yml 已加闸门：打包后跑 `dist/sidecar/sidecar.exe selftest`（惰性导入库全验，缺库构建即红）——新增任何 pip 依赖先补 requirements 再用
- **坏包只能升版本救，不能重打同版本 tag**：electron-updater 按版本号比对，同版本重传资产老用户不会收到更新提示（v0.1.18 坏包 → 当日发 v0.1.19 热修是正确姿势）
- 手动建 Release（正文自定）不冲突：softprops 会复用同 tag 既有 Release 并覆盖正文；也可完全不手动建
- 本机 `gh` 命令不是 GitHub CLI（npm 同名杂包）；调 GitHub API 用 `git credential fill` 取凭据当 token（验证过建 Release/删资产/触发 workflow/查 runs 均可，5000/hr 配额）
- 大文件上传若必须手动：curl --noproxy 直连可靠；python urllib 走系统代理传 253MB 流 25 分钟后回过一次 404（机制未查明，避开即可）
- 设置页 Settings.vue 有"检查更新/下载更新（NProgress 进度）/立即重启"三态；启动静默检查 + 顶栏新版本提示（v0.1.15 起）
- **更新下载状态架构（2026-08-25 修"切页丢状态"）**：`update-ready`/`update-progress` IPC 事件只广播一次，下载状态必须放全局 store（store.update.ready/downloading/percent/downloadError），监听随 initStore 注册、不随页面卸载；主进程记 readyVersion 并暴露 `app:update-state` IPC，renderer 重载后查询恢复，重新点下载时清零。模型/TRT 下载天生无此问题（WS 事件→全局 store，后端磁盘为真值）；模型下载 done 事件若在 WS 断线间隙丢失会永久卡进度条——WS onopen 清空 downloadProgress 自愈，下载中条目由下一进度事件（秒级）补回
- 手动检查与并发检查有 busy 守卫
- **上传资产禁用 `*.yml` 通配**（v0.4.0 实证）：electron-builder 会在 dist-app 产 `builder-debug.yml`，通配会把它一并传上 Release——已删资产并回滚为显式 `dist-app/latest.yml`
- **R2 备用下载源**（2026-09-02 起）：GitHub 连通失败自动回退 Cloudflare R2；2026-09-29 迁桶换域（桶 `yuzhen` / 域 `yuzhen-media.yeyushi.com`，旧桶删除）见 [[r2-mirror-update-fallback]]

**⚠ 双更新通道已整体移除（2026-09-29，随品牌化简化）**：设置页「更新通道」radio、后端 settings 的 `update_channel`（DEFAULTS+校验删除，load 弹残留键自愈）、主进程 IPC `app:set-update-channel` 与 allowPrerelease/channel 条件逻辑（现硬编码 allowPrerelease=false + channel='latest' + allowDowngrade=false）、CI 的 preview.yml 分支与 prerelease 标记全部拆除；R2 只剩 latest.yml。tag 一律正式版，不再发 `-preview.N`。旧预览客户端（channel=preview 找 preview.yml 404 → isChannelFileMissing 回落 GitHub；GitHub provider 对装机带预发布段默认 allowPrerelease=true 已被显式 false 覆盖）升级到首个正式版后自动并入稳定序列。以下双通道机制描述**仅作 electron-updater 行为的存档事实**，勿再当作现行设计：设置→应用与更新「更新通道」radio（稳定/预览），存后端 settings.json `update_channel`（stable/preview 白名单），主进程照 close_to_tray 模式经 IPC 收值，检查时映射 `autoUpdater.allowPrerelease`（显式 false 覆盖"装机带预发布段即 true"的默认）。预览版版本号 `X.Y.Z-preview.N`，release.yml 按 tag 含 `-preview.` 自动标 Release prerelease。**关键机制事实（源码+v0.4.0 发版实证，勿凭社区常见说法）**：①稳定通道客户端查 GitHub `releases/latest` 端点，天然排除 prerelease Release——存量旧客户端零改动即看不到预览版；②electron-builder 对 GitHub publish **不按版本号切 channel 文件名**（`getResolvedPublishConfig` 对 github 不写 channel，`computeChannelNames` 用 `publishConfig.channel||"latest"`），预览版也产 `latest.yml`；③预览通道客户端请求 `preview.yml` 404 后内建回退 `latest.yml`（GitHubProvider.js catch 分支），所以 CI 两种版本都只传 latest.yml（`*.yml` 通配会把 builder-debug.yml 传上 Release，v0.4.0 踩过已收紧回显式）；④主进程 newerVersion 已支持预发布段（0.3.9 < 0.4.0-preview.1 < 0.4.0），转正发同号正式版即把预览用户接回稳定序列。发预览版：三方版本号带 `-preview.N` + RELEASE_NOTES 写 `## vX.Y.Z-preview.N` 节 + tag `vX.Y.Z-preview.N`，其余全自动。
